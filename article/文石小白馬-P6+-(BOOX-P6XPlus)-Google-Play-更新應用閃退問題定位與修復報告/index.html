文石小白馬 P6+ (BOOX P6XPlus) Google Play 更新應用閃退問題定位與修復報告

2026-10-20
  • 設備型號：Onyx BOOX P6XPlus（文石小白馬 P6+）
  • 系統版本：Android 13 (2026-09-30_11-45_4.2.3-rel_0930_c353a5268)
  • Google Play 版本：com.android.vending 53.6.15-31 [0] [PR] 996698724 (versionCode=85361530)
  • 診斷日期：2026-10-19

一、 問題現象

在設備升級至 4.2.3 (2026-09-30_11-45_4.2.3-rel_0930_c353a5268) 系統後：

  1. 從文石桌面點擊 Google Play 商店圖示，可以正常進入主畫面。
  2. 但一旦在 Google Play 內點擊更新應用（或觸發其他內部頁面跳轉 startActivity），Google Play 會立即閃退（Crash）。

三、 根因分析（系統框架反編譯）

1. services.jar 中的 Activity 啟動攔截邏輯

反編譯 /system/framework/services.jar 中的 com.android.server.wm.ActivityStarter.executeRequest(Request)（對應源碼第 860–865 行），還原其字節碼邏輯如下：

// com.android.server.wm.ActivityStarter.executeRequest
String callingPackage = request.callingPackage;
if (!DeviceConfig.singleton().isGmsEnabled()
        && ActivityManagerHelper.isDisallow(callingPackage)
        && !ActivityManagerHelper.isSystemApp(callingPackage)) {
    throw new SecurityException("This app is not allowed to start because Google Play is disabled.");
}

2. framework.jar 中的 ActivityManagerHelper 與 Constant 判定邏輯

反編譯 /system/framework/framework.jar 中的 android.onyx.utils.ActivityManagerHelper 與 android.onyx.optimization.Constant：

// android.onyx.optimization.Constant
static {
    DISABLED_PACKAGES = new HashSet<>();
    DISABLED_PACKAGES.add("com.android.vending");
}

// android.onyx.utils.ActivityManagerHelper
public static boolean isDisallow(String packageName) {
    return Constant.DISABLED_PACKAGES.contains(packageName) && !gmsEnabled();
}

public static boolean gmsEnabled() {
    return OnyxMMKVConfigHelper.getBool("gms_enable", false);
}

public static boolean isSystemApp(String pkgName) {
    PackageInfo pkgInfo = ActivityThread.getPackageManager().getPackageInfo(pkgName, 1L, 0);
    return (pkgInfo.applicationInfo.flags & (ApplicationInfo.FLAG_SYSTEM | ApplicationInfo.FLAG_UPDATED_SYSTEM_APP)) > 0;
}

3. 為什麼會出現「能打開 Google Play，但點更新就閃退」的現象？

  • 從桌面打開 Google Play 時： 呼叫 startActivity 的發起方（request.callingPackage）是文石桌面 com.onyx。因為 Constant.DISABLED_PACKAGES 裡只有 "com.android.vending"，ActivityManagerHelper.isDisallow("com.onyx") 返回 false，因此桌面可以正常啟動 Google Play。
  • 在 Google Play 內部點擊「更新」時： Google Play 內部透過 Activity.startActivity 發起頁面跳轉，此時發起方 request.callingPackage 變成了 "com.android.vending"：
    1. DeviceConfig.singleton().isGmsEnabled()：國內版機型預設為 false。
    2. ActivityManagerHelper.isDisallow("com.android.vending")：檢查 /onyxconfig/mmkv/onyx_config 中的 gms_enable 鍵值。由於該值為 false，因此返回 true。
    3. !ActivityManagerHelper.isSystemApp("com.android.vending")：在 P6XPlus 上，GmsCore（Google Play 服務）預裝在 /product/priv-app/GmsCore（屬於系統應用），但 Google Play 商店（com.android.vending）安裝在 /data/app/ 下，屬於普通用戶應用（無 FLAG_SYSTEM 標記），因此 !isSystemApp 返回 true。
    4. 三個條件同時滿足，system_server 直接向 Google Play 拋出 SecurityException("This app is not allowed to start because Google Play is disabled.")，導致 Google Play 崩潰閃退。

4. 為什麼系統更新後 gms_enable 被改成了 false？

反編譯 /system/priv-app/kcb-release/kcb-release.apk（文石系統桌面 com.onyx）中的 com.onyx.common.setting.action.CheckGMSAction：

// com.onyx.common.setting.action.CheckGMSAction
private final boolean checkGooglePlayFromServer() {
    String baseUrl = getClusterInfo().loadOnyxApiBaseUrl();
    Response<ResponseData> response = RetrofitUtils.executeCall(
        ServiceFactory.getContentService(baseUrl).checkGooglePlay(Build.MODEL) // Build.MODEL = "P6XPlus"
    );
    if (response.isSuccessful() && response.body().isSuccessful()) {
        CheckGMSAction.checked = true;
        JSONObject data = (JSONObject) response.body().data;
        return data.getBooleanValue("allowed", false);
    }
    return false;
}

private final CheckGMSAction saveGMSEnable(boolean enable) {
    OnyxSystemMMKVUtils.putBool("gms_enable", enable);
    return this;
}

當設備升級系統並聯網後，CheckGMSAction 向文石伺服器查詢 checkGooglePlay("P6XPlus")，伺服器返回 allowed: false（或請求未通過），進而呼叫 OnyxSystemMMKVUtils.putBool("gms_enable", false) 將 /onyxconfig/mmkv/onyx_config 內的 gms_enable 覆寫為 false。

四、 修復方法與操作記錄

由於 /onyxconfig/mmkv/onyx_config 採用跨進程共享記憶體映射（MMKV.MULTI_PROCESS_MODE），且檔案權限為 -rw-rw-rw-，同時 /system/framework/framework.jar 中的 android.onyx.optimization.BaseMMKV 對 app_process 開放了 SDK,TEST-API 訪問權限，因此無需 Root 權限即可透過 ADB 直接呼叫系統 API 將 gms_enable 改為 true。

1. 透過 ADB 啟用 gms_enable

我們已將編譯好的修復工具推送到設備 /data/local/tmp/fix_gms.jar 並執行：

adb shell "CLASSPATH=/data/local/tmp/fix_gms.jar app_process / FixGms"

執行輸出：

Before gms_enable = false
After gms_enable = true

2. 日後若重啟設備後再次遇到閃退的快速恢復指令

因為 /data/local/tmp/fix_gms.jar 已經保留在您的設備中（除非恢復出廠設置，否則不會丟失），如果日後設備重啟聯網後被文石桌面再次改回 false，只需連上電腦執行以下一行指令即可立即恢復（無需重啟設備）：

adb shell "CLASSPATH=/data/local/tmp/fix_gms.jar app_process / FixGms"

對應的 FixGms.java 源碼備份如下：

import android.onyx.optimization.BaseMMKV;

public class FixGms {
    public static void main(String[] args) {
        boolean before = BaseMMKV.getBool("gms_enable", false);
        System.out.println("Before gms_enable = " + before);
        BaseMMKV.saveValue("gms_enable", true);
        boolean after = BaseMMKV.getBool("gms_enable", false);
        System.out.println("After gms_enable = " + after);
    }
}
